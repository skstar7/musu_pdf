This document is the project handover entrypoint for frontend, backend, and DevOps engineers.
Use it to understand what exists today, what remains, how teams should collaborate, and where each technical contract is defined.

## Handover Checklist (Manager / Tech Lead)

- Confirm each team can run its service independently.
- Confirm API contract alignment between frontend and backend.
- Confirm worker operation mapping for each core tool.
- Confirm environment variables are managed in a shared secret strategy.
- Confirm deployment target (single VM vs Kubernetes) before production hardening.
- Confirm security review of file handling and retention jobs.
- Confirm shared issue workflow and release cadence.

## High-Level Service Map

- Frontend (React/Vite): user experience and tool workflows.
- Backend (Spring Boot): API, validation, job orchestration, storage boundaries, download endpoints.
- Worker (Python/FastAPI): PDF operations.
- MongoDB: job metadata persistence.
- Redis: queue/status cache and rate controls (planned to be expanded).
- Nginx: reverse proxy and routing.

## Collaboration Contracts

- Frontend only calls backend API paths under `/api`.
- Backend never exposes raw storage directories.
- Worker is internal-only and not public-facing.
- API envelope shape is stable and versioned by backend.
- Any tool behavior change must update both:
  - [API_REFERENCE.md](API_REFERENCE.md)
  - frontend tool registry and config.

## Immediate Next Actions After Handover

1. Standardize local environments:
- Enforce Java 21 and Node 20+.
- Use Docker for MongoDB/Redis where possible.
- Use `JOB_STORE_MODE=memory` only for local fallback demos; keep `mongo` for shared QA/prod.

2. Validate core e2e path:
- Merge PDF upload -> process -> status poll -> download.

3. Add API integration tests:
- Job submission and download lifecycle.

4. Add worker regression tests:
- File outputs and page-range behavior.

## Glossary

- Job: asynchronous processing unit created by backend for an operation.
- Operation: normalized tool action (e.g., `merge-pdf`, `split-pdf`).
- Retention: configured storage window for uploaded and output files.
- Artifact: output file generated by worker and served by backend download endpoint.
